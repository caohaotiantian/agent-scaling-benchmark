#### RP-01 · No case set is in the repository, and none is recoverable from history

`.gitignore:56` ignores `benchmarks/ai_coding/cases/*/` by shape. `git ls-files benchmarks` returns

see `RP-05`, which shows that channel currently cannot deliver. Minimum viable improvement:
reference a checksummed bundle **by name** in `HANDOFF.md` so a replayer has something to ask for.

#### RP-06 · Per-case pass/fail is in no tracked artifact, so the central statistical claim cannot be checked

The pooled `p = 0.167` over 93 paired observations is the load-bearing result: it is what overturns
the single-run `p = 0.0312` and grounds the rule 任何模型比较至少 3 次重复.

**[measured]** `p = 0.167` is the exact two-sided binomial on `b:c = 13:6` pooled over three
rounds (HANDOFF:1033). The tracked export `ablation-two-models-3reps_20260810.json` carries five
`pairwise_comparisons`, **all against `two-glm51-r1`** — so round 1 gives `b=4, c=2` and the
correct r2↔r2 / r3↔r3 pairings are absent. Scanning all 13 calibrations for any value within 0.002
of 0.167 returns nothing.

Structural cause: the 10 **calibration** files carry per-case rows (`passes`, `attempts`,
`by_anchor`, `p_hat`, `point_biserial`) — which is why the distributions in §A.1 recompute. The 3
**ablation** files carry per-run aggregates only.

**Solution.** Same as `RP-02`. Additionally add a CI check that recomputes each published headline
from its own artifact and fails on drift.

#### RP-09 · Every documented install command is wrong, and two scripts undo the correct one

**[measured], reproduced twice.** Following the README exactly:

```
uv sync --extra dev  &&  uv run pytest tests/ -q
→ 1 failed, 712 passed
  FAILED tests/test_grading_env.py::TestManifestMatchesInstall::test_every_promise_is_importable

Worse, two scripts *prune the extra back out* even after a correct install. **[measured]**:

```
uv sync --extra dev --extra grading   → numpy 2.5.2 present
uv sync                                → ModuleNotFoundError: No module named 'numpy'

`install-hooks.sh:8` and `run_benchmark.sh:17`, or drop their implicit sync entirely. Consider
folding `grading` into the default dependency set so a bare `uv sync` suffices. **~30 min.**

#### RP-10 · Node is unpinned, undeclared, and the documented floor is wrong in a way that inverts results

There is no `.nvmrc`, no `package.json` `engines`, no `actions/setup-node` in CI, and `node` is
absent from the README quickstart. `languages.py` registers JavaScript unconditionally with no
`shutil.which("node")` check.

Probed across node 22.1 / 22.23.1 / 24.16.0 against the five real `.ts` cases in `_clean2026`
(`rev-bd78b451615c2a39`, `rev-0f878818dfebd4f3`, `rev-7ef5353e673af1af`, `rev-738db5f8753b49f2`,

- **node 24.16.0** — all five fail, correctly.

**Solution.** Commit `.nvmrc` pinning node 24; correct the floor in

are visible. **~2 hours. This is a correctness fix, not hygiene.**

#### RP-18 · Regeneration cannot reproduce the originals even with the DB and the gateway

Cases are LLM-written at `temperature: 0` with **no seed** and no pinned generator model, against a
live table read `ORDER BY start_time DESC LIMIT n` with `--since`/`--until` defaulting to `None`.

new fingerprint, so no tracked calibration is reusable or comparable.

**Solution.** Make `--since`/`--until` mandatory (or record a max `request_id`), and stamp
`{db_query_params, generator_model, code_version, harness_digest}` into every generated case. This
does not restore identity retroactively but stops the drift going forward.

### NF-01 · A shipped `conftest.py` exempts the interference gate entirely — **high**

`grading.py:47-57` lists the files that decide how pytest collects:

```python

    "conftest.py", "pytest.ini", "setup.cfg", "tox.ini",

if rel in shipped:

**[measured]** `benchmarks/ai_coding/cases/_clean2026/rev-bb519c7bf511ac8b.json` (also in

context.files      = conftest.py (role=impl, 13,345 bytes), test_conftest.py (role=test)
grader.mode        = script,  command = python -m pytest -q

grader.hidden_tests = ['test_conftest_spec.py']

```

The agent is *required* to edit the file pytest auto-loads, and can put
`collect_ignore_glob = ["*_spec.py"]` in it. `_retrytest` ships a `pytest.ini` the same way. This is
the exact file class the gate exists to catch.

**Solution.** Either scan shipped collection-control files regardless of the `shipped` exemption, or
extend `protect_visible_tests` to protect any file in `_COLLECTION_CONTROL_FILES` that is not itself
the gold target — and refuse to build a case whose gold *is* a collection-control file.

### NF-02 · Under `best-of-k`, `task_success_rate` **is** the oracle metric — **high**

**[measured]** `runner.py:161-171`:

```python
usable = [r for r in rows if not r.get("infra_error")] or rows
if strategy == "best-of-k":
    return next((r for r in usable if r.get("passed")), usable[0])
```

The selector consults `r["passed"]` — the grader's verdict, which no real system can see at
submission time. Therefore `row["passed"] == any(outcomes) == row["pass_at_k"]`, identically, for
every case; and `selection_hit_rate` (`report.py:174`) is exactly 1.0 whenever defined.

Not hypothetical: `configs/runs/passk.yaml:16,19` ships `max_attempts: 5` +
`selection_strategy: best-of-k`, and `configs/runs/ablation-matrix.yaml` row `passk-glm52` uses it.
**The production matrix McNemars an oracle-selected success rate against three honestly-submitted
ones.** `passk.yaml`'s own header comment claims the three quantities are separable.

This also refutes the report's "does well" item #7.

**Solution.** Either rename `success_rate` under `best-of-k`, or make the selector use a submit-time
signal (self-reported confidence, first non-error completion, a cheap pre-check). Until then, drop
the `passk` row from any matrix whose McNemar column is read.

### NF-03 · The export bundle's verbatim/provenance gate is blind to most of what it ships — **high**

def _substantive_lines(case):

        ...

`gold_files` and `hidden_tests` are never enumerated, yet `_scrubbed` (241-250) removes only

### NF-04 · `grade_case` is the only unguarded stage of the run loop — **high**

`runner.py:50-93` wraps `materialize_workspace` (line 59) and `agent.run` (line 80) in
`try/except Exception`. Then:

```python
grade = None
if not infra:
    grade = grade_case(case, workspace)   # no guard
```

Reachable raises inside `grade_case`:

- `grading.py:95` `path.write_text(...)` in `inject_hidden_tests` → `IsADirectoryError` if the agent
  created a directory at the hidden-test name. All 415 hidden tests sit at workspace root with
  predictable `*_spec.py` names.
- `grading.py:202` and `:234` in `_grade_gold` → `p.read_text(encoding="utf-8")` with **no
  `errors=`**, unlike every other read in the module. Any non-UTF-8 byte the agent writes to a gold
  path raises `UnicodeDecodeError`. There are 1,941 gold-mode cases on disk.
- `grading.py:81-83` reads every `.py` in the workspace → `PermissionError` on a chmod'd file.

Blast radius: `runner.py:373` `parallel_map(_job, cases, workers=workers)` and
`parallel_util.py:25-27` `results[i] = fut.result()`. One raising future propagates out of the
`ThreadPoolExecutor` block — after `shutdown(wait=True)` has paid for every other in-flight case —
so `results.jsonl`, `summary.json` and `report.md` are **never written** and the whole run's
completed work is discarded. Inside an ablation, `_one_guarded` swallows it and the row silently
vanishes from the comparison — the failure mode its own docstring names.

**Solution.** Wrap `grade_case` in the same `try/except Exception` as its two neighbours, mapping
the exception to `infra_error=True` with the detail. Add `errors="replace"` to the two `read_text`
calls. **One-line fix, highest value-per-character in this document.**

### NF-05 · `total_wall_time_h` and `throughput_cases_per_h` are wrong by up to 4× — **medium**

`report.py:48,60,129-130` sums per-case `wall_time_s` from the agent's own clock. Cases run
concurrently (`runner.py:373`, `workers = run_cfg.case_workers`). Summing concurrent intervals is
not elapsed time: at `case_workers: 4` (`configs/runs/baseline.yaml`) 总体耗时(h) overstates by up to
4× and throughput understates by the same factor. It also excludes workspace materialization,
`setup_commands`, git clone and the grader subprocess (up to 120 s/case) entirely.

`render_report_md` prints it under 总体耗时(h) and `ablation.py:150` copies it into the ablation
overview — where cost is supposed to sit beside the main metric (T7). Nothing records the actual
elapsed run duration.

**Solution.** Record a real `started_at`/`finished_at` on the run and derive elapsed from that;
keep the sum as `total_agent_cpu_h` under a name that does not claim elapsed time.

### NF-06 · `compose.donor_files` will plant collectable test files — **medium**

`compose.py:26-43` returns files where `f.get("role") in {"impl", None}`, while the module docstring
(lines 10-12) rests its safety argument on "none of them is a test file, so no runner collects
them". `role` is optional in `case.schema.json` (`required == ['path','content']`, `role` carries a
`"default": "impl"`), so a schema-valid case may omit it on a test file.

**Solution.** Filter on `f.get("role", "impl") == "impl"` **and** exclude anything matching pytest's

### NF-07 · The resume journal is crash-safe but the files it vouches for are not — **medium**

`checkpoint.py:52-75` goes to real trouble on the journal side (tolerating a half-written last line,
requiring `(self._dir / f"{cid}.json").is_file()`). But the existence test never parses the file,
and the write is not atomic — `io_util.py:23-27` uses `path.open("w")`, which truncates first, with
no tmp-file + `os.replace` anywhere.

`emit` calls `write_json` and *then* appends the `"written"` journal line, so the ordering is right;
but a kill between truncate and flush leaves a zero-length or half-written `<cid>.json` that `_load`
counts as complete and `skip_draft` refuses to regenerate. The resumed run reports
`resuming: N case(s) already written`, never re-asks the model, and the truncated file survives into
the set — where `cases.load_cases` raises `ValueError: Schema validation failed`.

**Solution.** Make `write_json` atomic (tmp file + `os.replace`), and have `_load` parse rather than
`is_file()`.

### NF-08 · The ablation matrix's `parallel:` key is dead code — **medium**

`ablation.py:182`: `parallel = max(1, int(parallel or matrix.get("parallel") or 1))`, while
`cli.py:240` gives `--parallel` a truthy default of `1` and `cli.py:774` passes it unconditionally.
`parallel or matrix.get("parallel")` therefore short-circuits on the first operand **every time**.

**11 of the 12 shipped ablation matrices declare `parallel: 3`**; only `ablation-matrix.yaml` says
1. `e2e_pipeline.sh:197-202` passes no `--parallel`. So every documented multi-row experiment runs
strictly serially at ⅓ the intended throughput, while `ablation_summary.json` records
`"parallel": 1` against a YAML that says 3. `configs/README.md:54-56` documents the concurrency
budget as if the key worked.

**Solution.** `parallel = max(1, int(parallel if parallel is not None else matrix.get("parallel", 1)))`
and make the CLI default `None`.

### NF-09 · `parallel_map`'s two branches disagree — **low**

`parallel_util.py:19-28`: the serial branch returns `len(seq)` items including every `None`; the
parallel branch ends `return [r for r in results if r is not None]`. A function that legitimately
returns `None` produces different results at `--workers 1` and `--workers 4`. The docstring says
"parallel map with ordered results" and does not mention the filter.

No live victim today (`runner._job` always returns a dict; `cli._gen_one` returns `None` on skip

is "swap agent and model, rerun, verify every reported number", and the filter permanently masks any
future `None`-returning caller.

**Solution.** Drop the filter; let callers filter explicitly.
